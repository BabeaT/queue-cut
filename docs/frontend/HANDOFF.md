## 视觉方向与已修正的问题

品牌使用天空蓝 `#55B8ED`、奶油白 `#FFF7E8`、暖白 `#FFFCF5`、荧光粉 `#F23891`、像素黑 `#171717`，搭配黑色粗描边、硬阴影和小圆角。中文正文使用系统中文字体，英文短标签使用本地 Press Start 2P。像素字体不用于长中文说明。

参考图用于风格和场景，标题、导航、按钮、规则和队列都是实际页面元素。用户金额统一用“排队币”。人物只承担品牌和队列插画，不加入角色奖励或养成。

原人物方案把一张合图假设成五个等宽格子，使用 `background-size: 500% 100%` 和固定背景位置。这导致压扁、红包截断及相邻角色残片，已修正。

当前人物原图为 `2172 × 724`，组件使用每个人物的实际矩形边界、独立 SVG `viewBox`、唯一 `clipPath` 和 `preserveAspectRatio="xMidYMax meet"`。原始 PNG 保留不变。请保留等比缩放与精确裁剪，切勿恢复等宽切图或拉伸填满。

离线 HTML 中的 SVG 图片地址也必须转换成 `./assets/`，生成脚本已经处理。更改原图尺寸或排列后，需要同步重测人物边界。

## 演示业务与操作路径

初始有五名模拟用户，阿明选择“不让”。输入昵称后免费入队，获得 100 排队币并排在第六位。

### 插队、上限保护和部分退款

1. 入队后点“我要插队”。
2. 目标选择第一位，会被阿明挡住，实际到第三位。
3. 越过小绿、小紫、小蓝，补偿分别为 0.30、1.00、0.50，共 1.80 排队币。
4. 最多愿付输入 1.70，确认后显示失败且不扣余额。
5. 改为 1.80 后成功，产生三笔独立冻结记录。
6. 在记录里“模拟对方退出”，只退对应费用。
7. 按演示控制中的叫号与核销操作推进，双方完成消费后才给被越过者结算。

### 收到补偿并到账

1. 重置后重新入队。
2. 点“模拟有人插我”，新增一笔按自己的生效报价计价的待结算补偿。
3. 点“前方顾客完成消费”，插队者先消费，自己的补偿仍冻结。
4. 点“叫下一位”，再点“核销当前叫号”，双方消费后补偿进入可用余额。

### 不让和未消费

开启“不让”并确认，等待两个模拟区块，再点“模拟有人插我”，该操作会被挡住且不产生补偿。主动退出、过号和收摊会按每笔关系退款。重置需确认，刷新也能重置。

演示金额内部以十分之一排队币的整数保存，展示时再格式化。真实合约的金额换算在另一套 `wallet.ts` 中，不能把演示单位直接传给合约。
