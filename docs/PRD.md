## 一、一句话和定位

**一句话**：在以太坊上插队，钱给了矿工；在这里插队，钱给被你插队的每一个人。

**定位**：一场「给排队时间定价」的现场实验。
- 现在想快一点，钱给了黄牛、加速包和 VIP 通道；老实排队的人什么也得不到，还会被插队。
- 我们让插队公开、自愿、付费，而且钱付给被越过的每一个人。
- 老实排队的人**永远不花钱、不亏钱**。

**场景**：
- **主场景（现场演示）**：网红店、奶茶店排队。真人排队，买真奶茶。
- **场景二（路演收尾口头讲一句，不开发）**：演唱会回流票的候补队。同一套机制可以管候补队的先后顺序。

## 三、规则（定稿）

### 3.1 入队
- **免费**，没有押金，也没有占位税。
- 入队时报一个**让位价**，意思是：「谁出这个价，我就往后让一位。」也可以选**「不让」**。两种都不花钱。
- 一个地址同一时间只能在队里排一个位置。

### 3.2 让位价：挂价即同意
- 让位价是每个人**提前挂出来的价**，相当于商品的标价。有人出这个价插队，**不需要再问他、等他同意**，挂价本身就是同意（报价即承诺）。
- **不设上限**。报价高过商品价格，结果等于「不让」：没人插得起你，也没有人吃亏。让位价是你排队时间的价值，不是商品的价值，平台不替你定。
- 手机上的滑杆范围是 0.1–10，常用档位 0.2 / 0.5 / 1 / 3，另有「不让」开关。这只是体验上的约束，合约不限价。
- 随时可以改价，或切换「不让」。**改价 2 个块后才生效**（约 0.6 秒），防止有人看到别人要插队，临时涨价敲竹杠。

### 3.3 插队：插进去，按人分别付
- 第 i 位想插到第 j 位（j < i）：**插进第 j 位**，原来第 j 到第 i−1 位的人每人往后退一位。
- **每个被越过的人，按他自己的让位价分别付**，总价 = 这些人的让位价之和。一笔交易给所有人记账，被越过的人手机同时收到提醒。
- **遇到选了「不让」的人，就停在他身后**，只付他身后那几个人的钱。手机上提前显示最多能插到第几位。
- 交易带「最多愿付」上限：实际要付的钱超过你确认时看到的价，整笔交易失败，不会多扣。
- **插队前先看明细**：「越过 7 人：阿明 0.5、小红 0.2……合计 6.2」，并提示报价最高的那一位（例如「第 7 位报 3，只插到第 8 位只要 1」），你自己决定插到哪。

**为什么是「插进去、按人付」，不是另外两种做法**（讨论过，已否掉）：

| 做法 | 问题 |
|---|---|
| 两人换位（10 号和 5 号对调） | 本质是**卖位置**，黄牛早早排到前面再换给急的人收钱，正是黄牛生意；也失去「一笔交易给 N 人到账」的画面 |
| 合计后平分给被越过的人 | 报高价的人只拿到平均数，等于强迫他低价让位，「报价即承诺」不成立；报低价的人反而多拿，大家会乱报 |
| 每次插队都实时征求同意 | 越过 30 人要等 30 人点同意，一个人没看手机就卡住，演示做不了 |

### 3.4 结算：双方都消费了，钱才归被插的人
- 插队的钱**按人分别记账、分别冻结**。越过 7 个人，就是 7 笔独立记录。
- **每一笔单独结算**：
  - 插队的人消费了，被插的人也消费了 → 这一笔归被插的人；
  - 任何一方没消费（叫号没来被过号、主动退出、打烊没轮到）→ 这一笔**原路退回插队的人**。
- 越过 7 个人，其中 2 个最后没消费，就只退这 2 笔，其余 5 笔照付。
- 道理：排队时间只由真正消费的人构成，钱只在真的耽误了你时才算数。

### 3.5 叫号、核销、过号
- 店员叫号，叫的是队伍最前面的人。
- 来了 → 店员按「核销」，算已消费。
- 没来 → 店员按「过号」，这个人出队，不耽误后面的人。现实里叫号不来就过号，我们也一样。
- 店员核销是链下动作，链上结算以这一下为准。这是预言机问题，**路演时主动承认**；演示时我们自己当店员，每一次核销、过号都在大屏上公开。

### 3.6 退出和收摊
- 随时可以退出，算没消费。
- 打烊时店员按「收摊」，队里剩下的人都算没消费，没结算的钱全部原路退回。

### 3.7 位置不能转让
合约里**没有**转让位置或换位的函数。想往前，只能按 3.3 付钱插队。

### 3.8 结算汇总

| 情况 | 他收到的插队钱 | 他付出的插队钱 |
|---|---|---|
| 消费了 | 对方也消费了的那几笔归他；对方没消费的那几笔退回 | 对方也消费了的不退；对方没消费的那几笔退回给他 |
| 过号、退出、打烊没轮到 | 全部原路退回给插队的人 | 全部退回给他 |

**没有任何一种情况会让老实排队的人亏钱。**

## 四、防黄牛和边界

| 黄牛玩法 | 为什么行不通 |
|---|---|
| 抢到前排，再高价倒卖位置 | 合约里没有转让和换位函数 |
| 开小号排队，专收插队红包 | 不消费一分拿不到，全部退回插队的人 |
| 刷大量小号占满队伍 | 叫到不来就过号，挡不住任何人 |
| 自己的号插自己的号刷榜 | 钱左手倒右手，没有收益 |

收尾金句：**黄牛要么白忙一场，要么变成真顾客。**

**边界（主动划清，不宣称能解决）**：黄牛把买到手的东西（奶茶、门票）再高价转卖，是**商品转售**问题，靠限购、实名制解决，不在我们的范围。路演一句话：「我们管的是队伍：位置不能倒卖，插队的钱给排队的人；买到手的东西再转卖，是限购和实名制的事。」

**「不让」的副作用**：选「不让」不花钱，相当于在队伍里立了一堵墙，挡住他身后所有想插队的人。我们不加钱（加钱就又回到占位税，老实人要交钱），而是在大屏和手机上公开显示「此人挡住了 N 人」，靠社交压力。这在 Demo 里正好是第二幕的素材。

## 五、产品页面

### 5.1 手机 H5：`/m`
- **入队页**：输入昵称，设让位价（默认 0.5）或「不让」，点「排队」。
  - 这一下点击同时解锁 iPhone 的声音；
  - 后台生成浏览器内钱包，领 100 排队币，入队。用户全程不碰钱包插件和测试币。
- **主页**：
  - 我的位置：大字「第 N 位」，下面写「前面还有 N 人 · 队伍共 M 人」；
  - 冻结收益 🔒：「你和插队的人都消费后到账」；可用余额单独显示；
  - 让位价滑杆 + 常用档位 + 「不让」开关；选了「不让」显示「你挡住了身后 N 个人」；改价后显示「将在块 #xxx 生效」；
  - 插队：选要插到第几位，显示**明细**（越过谁、各付多少、合计）和「最多能插到第 X 位」，确认后签名；
  - 「不排了」按钮（二次确认）。
- **到账提醒**：安卓震动；iPhone 播提示音 + 全屏闪红（iPhone Safari 不支持网页震动）。
- **状态页**：叫到你（「请到柜台」，震动 + 声音）、已核销（到账金额）、已过号或已退出（退回了多少）。

### 5.2 大屏：`/screen`
- 顶部：标题、口号、右上角块号，每块跳一下，标「Monad 测试网 · 0.3 秒出块」。
- 队列：一字排开，每人显示 emoji 头像、昵称、让位价（「不让」显示 🧱 和「挡住 N 人」）、冻结收益 🔒；黄牛卡片单独配色；位置变化有平滑动画。
- **插队特效**：一道光从队尾冲到目标位置，被越过的人头上同时冒红包「XX 被越过，收到 0.8」；横幅「XX 插队到第 N 位 · 同一个块 #xxxx · N 人到账 · xxx ms」。
- **结算特效**：到账显示金色「✅ 到账」；退回显示灰色「↩ 退回给 XX」，并飞向插队的人；过号的人变灰。
- 柜台区：当前叫到的人。
- 黄牛面板：20 个号的两条曲线，「冻结中」和「实际到手」；「实际到手」一直是 0。
- 底部指标：插队次数、红包数、已到账笔数、原路退回笔数、最近一次插队的链上确认毫秒、全场到账毫秒（多少台手机回执）、gas limit 和 gas used、交易链接。
- **同块统计**：「这一块进来 N 人 / 处理 N 笔」，开场全场入队时最显眼。
- **价格分布**：全场让位价的平均值和分布，配一句「广州人排一位，平均值 0.6」（收尾梗，见 PITCH.md）。
- 入队二维码（扫码排队）。

### 5.3 店员台和导演台：`/stage`（需要口令）

## 八、高并发怎么讲

- **不把高并发当卖点**：往届上海站 ENTER Market 演示过 40 部手机同块上链，没获奖；深圳站「去中心化抢票平台」主打高并发抢票，排第 17 名；导师也建议不吹并行。
- 高并发**只作为证据**出现在两个时刻：开场全场入队（同块统计）、第一幕插队（一笔交易几十人到账，同时全场还在改价）。
- 如实讲：改让位价时每个人只写自己的数据，互不冲突，适合并行执行；插队会改动整条队伍，是串行的，不吹成「插队也并行」。

## 九、技术方案摘要

详见 [ARCHITECTURE.md](ARCHITECTURE.md)。
- 合约 `QueueCut.sol`（Foundry，Monad 测试网），加上 OpenZeppelin 的 `ERC2771Forwarder` 实现代付 gas。
- 后端（Node + TypeScript）：中继、索引器、WebSocket 推送、店员台和导演台接口。
- 前端（Vite + React + viem）：`/m`、`/screen`、`/stage`。
- 黄牛：20 个 EOA，各自用自己的地址发交易。

## 十一、评委追问预案

| 问题 | 回答要点 |
|---|---|
| 商户为什么要用？ | 这是一次「给排队时间定价」的实验，商户端是假设。我们证明的是：插队可以公开定价，钱给排队的人，而不是黄牛和平台 |
| 被插队的人同意了吗？ | 挂价即同意：让位价是他自己挂的，谁出这个价他就让；不想被插就选「不让」 |
| 为什么不平均分？大家都只推后一位 | 平分会让报高价的人被迫低价让位，「报价即承诺」不成立，大家会乱报；各自报价、各自拿，每个人拿到的正好是自己开的价 |
| 让位价要不要设上限？ | 不用。报得比商品还贵，结果就是没人插得起，等于「不让」，没人吃亏 |
| 为什么不是两人换位？ | 换位就是卖位置，正是黄牛的生意；插进去、按人付，没有人能卖一个完整的位置 |
| 链上队伍和店里叫号怎么一致？ | 靠店员核销锚定，这是预言机问题，我们公开承认 |
| 为什么非要 Monad？ | 0.6 秒终局，队伍和现实同步；一笔交易给几十个地址分账，gas 可以忽略。给出大屏实测数字，不吹并行 |
| 这不就是把黄牛的钱分给排队的人吗？ | 对，而且更进一步：位置不能转让，插队的人必须真消费，钱不进平台口袋 |
| 黄牛买到东西再倒卖呢？ | 那是商品转售，靠限购和实名制；我们管队伍，主动划清边界 |
| 「不让」会把插队市场堵死吗？ | 会，所以公开显示「挡住了 N 人」，靠社交压力；不加钱，加钱老实人就要交钱了 |
| 按人头定价，两人桌、四人桌呢？ | Demo 按人头；按桌是下一步 |
| 钱要冻结很久吗？ | 要等双方都消费完，这是「钱只在真耽误你时才算数」的代价 |
| 为什么上链，中心化 App 不行吗？ | 报价、付款、冻结、解锁每一步都不用信任平台；平台改不了顺序，也抽不了成 |
